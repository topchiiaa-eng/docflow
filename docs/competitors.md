## Выводы

1. **Ниша реальна: у провайдеров «несколько юрлиц» = переключатель, а не лента.** Диадок, СБИС, DocuSign решают задачу через «одна учётка → несколько организаций → переключение контекста». Ни у одного проверенного российского провайдера не найдено единого списка входящих по всем юрлицам с общими фильтрами и единой очередью «на подпись». Единственный российский «один экран по всем компаниям» — Контур.Экстерн для обслуживающих бухгалтерий — про отчётность, не про ЭДО с контрагентами.
2. **Обязательно «по рынку»:** входящие бесплатны у всех — брать деньги «за документ» нельзя; минимум три уровня ролей; уведомления о смене статуса; история/журнал действий; фильтры по типу, контрагенту, статусу, дате; подписание только КЭП на стороне пользователя.
3. **Дифференциаторы ДокПотока:** (а) кросс-организационная лента и единая очередь «на подпись» с явным подтверждением по роли — провайдеры дают это только внутри одного юрлица; (б) дешёвая альтернатива платным модулям согласования и «дополнительной подписи» Диадока (10–230 тыс. ₽/год + 40 тыс. ₽/год на юрлицо); (в) журнал подписаний в разрезе «кто / в какой организации / по какой роли» — audit-trail, которого в мультиорг-режиме у провайдеров не видно.
4. **Ценовой ориентир:** модель Dext Practice — фикс за юрлицо в месяц, без платы за документы; верхняя граница — стоимость модуля согласования Диадока на одно юрлицо.
5. **Главный риск — зависимость от Диадока.** Продукт строится на API одного провайдера (аутентификация, лимиты, условия для сторонних приложений), а Контур может добавить «единую ленту» сам — техническая база (мультиорг-учётка) уже есть. Митигация: абстракция провайдера (`EdoProvider` — уже заложена; СБИС/1С-ЭДО как вторые источники) и позиционирование на процессе (роли, очередь, журнал, уведомления), а не только на агрегации.
6. **Второй риск — 1С как «теневой конкурент»:** для групп с многофирменным учётом в одной базе «Текущие дела ЭДО» уже даёт общий список к исполнению. ДокПоток должен выигрывать веб-доступом для операционных менеджеров без 1С, ролями и уведомлениями.

**Как выводы повлияли на проект:** пункты 2–3 подтвердили состав экранов проектной работы — единая лента, очередь «на подпись», журнал подписаний, управление организациями и ролями; пункт 5 — решение сохранить интерфейс `EdoProvider` как границу между продуктом и провайдером.
