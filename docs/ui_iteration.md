# Итерация интерфейса по замечанию защиты

Замечание: «интерфейс выглядит совсем непроработанным; не планируете доработать на основании урока по интерфейсам?». Ниже — честная диагностика, что именно было не так, и какие паттерны из урока применены. Сравнение «до/после» — `docs/screenshots/` (файлы `live-*.png` пересняты с production после итерации).

## Диагностика: почему выглядело «каркасом»

| Проблема | Причина | Что сделано |
|---|---|---|
| Жёсткие **чёрные рамки** у всех карточек и полей | В Tailwind v4 класс `border` без цвета рисует `currentColor` (цвет текста) — 25 мест в коде. Это не «вкус», а дефект | Базовый слой `border-color: slate-200` для всех элементов (как в v3) + единая утилита `.card` |
| Нет визуальной иерархии | Заголовок страницы 18px, всё одного веса; навигация — текстовые ссылки в шапке | Заголовок 24px + подзаголовок-пояснение; сайдбар с иконками (десктоп) и нижняя панель вкладок (мобильные) — концепция «Дашборд» из ДЗ-3 |
| Строки документов «одинаковые» | Тип документа — только в тексте; непрочитанность — тонкая полоска слева | Цветной чип типа (УПД / Акт / Счёт / Договор), точка непрочитанного, суммы в моноширинных цифрах, статус-бейдж |
| Загрузка — спиннер в пустом экране | Нет представления о будущей структуре | Скелетон экрана (KPI, фильтры, список, панель) |
| Пустые состояния — текст в рамке | Нет иллюстрации и действия | `EmptyView`: иллюстрация + текст + CTA («Сбросить фильтры») |
| Результат действия незаметен | После подписания менялся только бейдж | Тосты «Подписан: …», «Документ добавлен», «Документ удалён» (`aria-live`) |
| Карточка документа — список строк | Нет шапки, статус теряется, файл — серый квадрат | Шапка с типом/организацией и статусом (тонируется по статусу), сетка атрибутов 2×2, блок файла с иконкой, основное действие внизу |
| Фильтр организаций — `<select>` | Не видно распределения документов | Чипсы с количеством (паттерн концепции 1) |
| Нет табличного режима | Обещан в ТЗ как US-10 (паттерн концепции 3 для сверки) | Переключатель «карточки / таблица», выбор сохраняется в `localStorage` |
| Экран входа — одинокая форма | Нет ценностного предложения | Сплит-экран: слева — три тезиса продукта, справа — форма; на мобильных — только форма |
| Нет единых токенов и фокуса с клавиатуры | Цвета и отступы — «по месту», `focus:outline-none` без замены | `@theme`-токены (`brand-*`, `ink`), утилиты `.btn-primary/.btn-secondary/.input/.label`, глобальный `:focus-visible` |
| Иконки отсутствуют | — | 15 линейных SVG-иконок без внешней библиотеки (CSP, размер бандла +0 КБ зависимостей) |

Что осталось сознательно: тёмная тема (переключатель) — вне MVP; drag-and-drop файла — вне MVP.

## Как это делалось (процесс, а не только результат)

1. **Диагностика по скриншотам production** (puppeteer, свежий пользователь) → список дефектов выше; «чёрные рамки» найдены как первопричина через поиск по коду (`grep` бесцветных `border`).
2. **Правила сохранены:** все 43 теста и e2e-селекторы (роли, aria-label, тексты кнопок) не менялись — рефакторинг вёрстки без изменения контракта тестов. Единственная правка в тестах — две навигации (сайдбар + нижняя панель) → `getAllByRole(...)[0]`.
3. **Проверка итерациями по скриншотам:** первый прогон показал два новых дефекта — горизонтальное переполнение (`1fr` без `minmax(0,1fr)` в grid, классика) и перекрытие иконкой плейсхолдера поиска (порядок утилит `px-3` в `.input` vs `pl-9`); второй — обрезанные названия (`truncate` → `line-clamp-2`). Три цикла «скриншот → правка → скриншот».
4. **Проверка на production после деплоя:** post-deploy job `verify` + скрипт скриншотов под свежим пользователем.

## Что из урока по интерфейсам применено

- Иерархия: размер/вес/цвет — три уровня (заголовок, подзаголовок, вспомогательный текст).
- Системность: токены цвета и отступов, утилиты-компоненты вместо «классов по месту».
- Состояния: loading-скелетон / error / empty с действием / success-уведомление — для каждого экрана.
- Обратная связь: тосты, `aria-live`, видимый фокус, `aria-pressed` у переключателей.
- Навигация по платформам: сайдбар на десктопе, нижние вкладки на мобильных.
- Сканируемость списков: цветовое кодирование типа, точка непрочитанного, табличные цифры, табличный режим для сверки.
- Прогрессивное раскрытие: карточка документа открывается рядом (master-detail), на мобильных — поверх списка.
