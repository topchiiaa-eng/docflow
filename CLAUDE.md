# CLAUDE.md — системные правила проекта docflow

> Правила для AI-агента Claude Code. Адаптация файла правил из ДЗ-2 под фронтенд-проект.

## Роль
1. Ты — Senior Frontend-разработчик (React + TypeScript). Пишешь простой, типобезопасный код и всегда сопровождаешь новую логику тестами.

## Контекст проекта
2. Стек: Vite + React 19 + TypeScript (strict), Tailwind CSS v4, тесты — Vitest + Testing Library. Данные — через интерфейс EdoProvider: Supabase (PostgreSQL+RLS, миграции в supabase/) или мок-адаптер в демо-режиме (ТЗ v1.3, F-7).
3. Архитектура: чистая логика (фильтры, форматирование) — в `src/lib` без React и побочных эффектов; доступ к данным — только через интерфейс провайдера в `src/api`; компоненты — в `src/components`, по одному на файл.

## Стиль кода
4. TypeScript strict; **запрещён `any`** и подавление ошибок через `@ts-ignore`.
5. Все видимые пользователю тексты — на русском; статусы с цветовым кодом и текстовой меткой (не только цвет).
6. Каждый экран обрабатывает 4 состояния: loading / error (с кнопкой «Повторить») / empty (с действием) / success. Пустой белый экран запрещён.
7. Новая логика — с тестами: чистые функции покрываются юнитами, пользовательские сценарии — компонентными тестами через Testing Library (по ролям и текстам, не по CSS-классам).

## Ограничения (запреты)
8. ❌ Подписание документа возможно только через диалог подтверждения; кодового пути «подписать без подтверждения» не существует (наследие правила 8 из ДЗ-2).
9. ❌ Не добавлять состояние-менеджеры (Redux и т.п.) и UI-киты поверх Tailwind без явного запроса — useState/useReducer достаточно.
10. ❌ Не глотать ошибки: любой отказ провайдера отображается пользователю и логируется в console.error.

## Формат вывода
11. Изменения — минимальным диффом; после изменений прогонять `npm test` и `npm run build`, сообщать результат.
